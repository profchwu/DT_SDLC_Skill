# SDLC quality gates

1. Requirements ready: scope, non-goals, acceptance criteria, data, errors, and unresolved items are explicit.
2. Design ready: architecture, interfaces, deployment, secret boundaries, security and human-safety risks, accessibility when applicable, and test strategy are reviewed.
3. Build ready: tasks are ordered and each increment has a verification method.
4. Verification ready: environments and fixtures are controlled; expected results are known.
5. Release ready: required tests pass; production secrets, monitoring, migration, rollback, and incident ownership exist; known limitations are documented.
6. Operate ready: monitoring, ownership, incident response, and maintenance expectations are defined.

Reference families: ISO/IEC/IEEE 12207, ISO/IEC/IEEE 29148, ISO/IEC/IEEE 16085, Agile Manifesto, and context-appropriate security standards.
